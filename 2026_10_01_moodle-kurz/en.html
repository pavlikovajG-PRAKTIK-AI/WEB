Moodle – revising a course

A Moodle course is saved as a single backup file (.mbz). The AI tool unpacks the file, edits the content as you instruct and packs it again. You first restore the edited backup in a test course and then, if it is in order, in the live course.

Preparation

What you need

moodle.pf.ujep.cz · Moodle 3.11

Moodle → .mbz backup → AI edits → new .mbz → test course → check → live course

  • A teacher role with editing rights in the course. If you cannot see Backup and Restore in the course menu (the cog icon), contact your Moodle administrator.
  • An empty test course in which you are a teacher.
  • An AI tool that can work with files and run code. The procedure has been tested with Claude Code in the Claude desktop app.
Basics

Procedure

  1. Back up the course

    In the course, click the cog icon → Backup. In the first step, untick Include enrolled users. Click Next until you reach Perform backup, then Continue. Download the .mbz file using the Download link.

    A backup without users contains no student data, so none of it reaches the AI tool.

  2. Instruct the AI tool

    Upload the .mbz file to the AI tool and start with an overview, not with changes:

    Go through this Moodle course backup. List the sections and pages and suggest what to update. Do not change anything yet.

    Choose the suggestions you want and ask for them:

    Edit the pages in sections 2–4 according to points 1, 3 and 5. Do not delete anything without my consent.

    With AI you can, for example, correct and update texts, give pages a consistent look, check links, add new pages and renumber sections. For a new type of activity (assignment, workshop, H5P), the AI tool needs an example from one of your actual backups.

  3. The AI tool packs and checks the backup

    An .mbz file is a compressed archive with special rules (it is not an ordinary ZIP file). So add this to your instructions:

    Pack the result as a Moodle backup (.mbz): tar.gz in ustar format without PAX headers, with a newly generated .ARCHIVE_INDEX file as the first entry. Write the XML files with the header <?xml version="1.0" encoding="UTF-8"?> and LF line endings. Validate the backup and keep it under 100 MB.

    100 MB is the upload limit on moodle.pf.ujep.cz.

  4. Restore into the test course

    In the test course: cog icon → Restore → under Import a backup file, choose the new file → Restore. Under Restore into this course, select Delete the contents of this course and then restore and click the button below that section. Then click Next until you reach Perform restore, then Continue.

    Go through the course: section order, pages, images, links. You check the content for factual accuracy yourself, as AI can make mistakes.

  5. Restore into the live course

    Proceed as in step 4, but check these restore settings:

    • Keep current roles and enrolments: Yes (choosing No unenrols all students)
    • Keep current groups and groupings: Yes
    • Overwrite course configuration: No

    Caution: The option Delete the contents of this course also deletes student work in activities (forum posts, quiz attempts, assignment submissions, grades, activity completion). If the course already contains student work, do not restore the backup; instead, ask the AI tool for ready-made HTML pages and paste them into Moodle yourself (the HTML button in the editor).

  6. If the restore fails

    Click More information about this error and paste the full text into the AI tool. The message “progress() value out of range” means the archive was packed incorrectly. The message “Unknown backup format” means an error in the XML files (header or line endings). In both cases, the AI tool corrects the backup and packs it again. Always upload the newest file, and delete older backups with the same name on the Restore page so that they are not mixed up.

Summary. Back up without users. Restore the edited backup in a test course first, and check the content yourself before publishing it.
