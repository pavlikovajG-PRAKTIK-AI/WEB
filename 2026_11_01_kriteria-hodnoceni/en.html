Assessment Criteria and Test Versions

You already know how to write a test with a chatbot. This worksheet takes you a step further: Gemini will help you try out your assessment criteria before you start marking with them, and prepare enough equivalent questions for a test that students can receive different combinations. The questions, the criteria and the final marks remain in your hands.

Preparation

A working folder and Gemini

Always sign in to Google Drive and to Gemini with your work account in the g.ujep.cz domain, not with a personal Google account. Otherwise Gemini may not find the files in your working folder.

Put all the materials for your course in one Google Drive folder: the syllabus, exam questions, course textbooks or lecture notes, slides, and any earlier assessment criteria. You then attach them to the chat as files, and you do not copy anything into the chat window.

  1. Open gemini.google.com and check that you are signed in with your g.ujep.cz work account.

  2. In the prompt box, click the model menu on the right and choose Deeper analysis (4 Neon). In the same menu, open Thinking level and choose High. Check the thinking level every time before you start working.

  3. In a new chat, click + and choose Add from Drive. Select the files from your working folder that you need for the task.

  4. You do not have to type your prompt; you can dictate it using the microphone icon. Minor transcription errors usually do not matter, but always check the output.

Tips

Better prompts

  • Ask for clarifying questions. End your prompt with: Before you start, ask me about anything you need to know to do this task well. Gemini will then usually ask for the details missing from your prompt.
  • Output as a table. If you ask for the output as a table, you can usually copy it into Word or Excel without retyping.
  • One task, one chat. Keep the whole criteria procedure in one chat from start to finish, so that Gemini has all the previous steps in front of it.
Recap

Rules for good questions

  • Each question tests one syllabus topic, and together the questions cover the syllabus, or the part of it that the test assesses.
  • The wording of each question is unambiguous, and students can understand it without further explanation.
  • A question contains no double negatives and does not give away the answer to another question.
  • In multiple-choice questions, only one answer is correct, and the incorrect options are plausible and of similar length to the correct one.
  • The questions test not only recall but also the application of knowledge and the reasoning behind it.

You can paste these rules into Gemini together with your questions and ask it to check your questions against them.

Core task

Assessment criteria that hold up

Carry out steps 1 to 4 in one chat.

  1. Draft the criteria as a table

    Draft assessment criteria for these exam questions as a table: rows = questions, columns = grades. Course: [fill in] Type of exam: [oral / written with open answers] Grading scale: [fill in] The questions and the syllabus are in the attached files. For each question, state: - what an answer must contain for the student to pass, - what distinguishes an answer at each grade (in the table cells), - common errors and inaccuracies that lower the grade (below the table). Base the criteria only on the attached syllabus and materials.

    Have the draft checked:

    Go through the criteria and list separately the places where the boundary between grades is unclear or where a criterion does not follow from the syllabus. Return the corrected criteria in full, with a list of changes.

  2. Test the criteria on invented answers

    Try the criteria out on invented answers, not on students' answers.

    For each question, write invented student answers: an excellent one, a borderline one (just at the pass mark), a failing one and one containing a typical error. Shuffle the answers and do not label their intended quality. Give the key separately at the very end. Do not grade them yet.

    Grade the answers yourself first, without reading the key. Then ask Gemini to grade them against the criteria table and to justify each grade by referring to a specific cell. Wherever your grade differs from Gemini's or from the key, make the criteria more precise.

  3. Devil's advocate

    Ask Gemini to try to get round the criteria:

    Play the role of a student who wants to pass with as little knowledge as possible. Write an answer that formally meets the criteria but does not demonstrate knowledge of the subject. Then suggest how to revise the criteria so that such an answer would fail.

  4. The final version of the criteria

    Have all the revisions combined into one final table:

    Combine all the revisions so far into one final table of criteria. Every criterion must follow from the syllabus and must be verifiable from the student's answer. Replace vague words (well, adequately, sufficiently) with a concrete description of what the answer contains. The boundaries between grades must be unambiguous and the grades must not overlap. Below the table, list what you changed.

    For an oral exam, also ask for follow-up questions for each exam question that will help you decide between neighbouring grades.

  5. Adapt the criteria to your own practice

    Go through the criteria and adjust them to reflect how you actually mark. You can share the final criteria with students before the exam.

Extension

Different versions of a test

  1. In Moodle

    For each question in the test, have Gemini create a set of equivalent versions in GIFT format (following the procedure in the October worksheet), and save each set in its own category:

    For each question in the test, create [fill in number] equivalent versions in GIFT format. The versions test the same topic, with the same question type and the same difficulty, but differ in the example, data or text. Head each set with the line $CATEGORY: [test name]/[question number] [topic] with a blank line before and after it. The test is in the attached file.

    When importing into the question bank, tick Get category from file. Then add a random question from each category to the quiz. On each attempt, Moodle selects one question at random from each category, so students are likely to receive different combinations.

  2. On paper

    When several groups sit the test one after another, prepare a second version of the same test:

    Create version B of the attached test. Each question in version B must test the same topic, with the same question type and the same difficulty, as the corresponding question in version A, but it must not be possible to copy its answer from version A. Put the questions in version B in a different order. At the end, add a table: number in version A, number in version B, topic, question A, question B, and an answer key for both versions.

  3. Checking difficulty

    Ask Gemini to compare the versions and list any questions that are clearly easier or harder than the others in the same set. Whether the versions are equivalent is your decision.

Limitations

Student data and checking the output

Do not put students' names, their real answers or their results into the working folder or into Gemini. Use invented answers to test the criteria. Gemini can make mistakes in subject content and in estimating difficulty, so always check the criteria and the test versions yourself before you use them.

Summary. Keep your materials in one Drive folder and attach them to the chat as files. Test the criteria on invented answers and let a devil's advocate challenge them. Save equivalent questions in categories and build the quiz from random questions.
